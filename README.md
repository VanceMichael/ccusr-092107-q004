# 景区退出整改资产账

保存景区评级检查、设施风险、整改项目和退出决定。

## 领域资料

`contracts/context.schema.json` 约定基础资料格式，`fixtures/context.json` 提供不含真实个人信息的示例。代码模块只负责读取和校验这些资料，后续业务服务可以沿用其中的领域标识与版本约定。

当前资料记录了以下业务事实：

- 部分景区因安全管理、服务弱化和数据造假被处理
- 主管部门可采用抽查、暗访和游客反馈等方式监督
- 被降级景区尝试通过新业态改善经营

## 本地校验

运行项目自带测试可确认示例资料能够读取，且领域标识、版本和事实列表完整。示例中的编号均为虚构值，不包含账号、凭据或真实主体信息。

## 动态退出与资产盘活后台

`src/` 下的模块把上述领域资料扩展为可执行的后台：

- `ledger.js` —— 七类资料分账留存：评级依据、明查暗访、游客反馈、设施风险、运营数据、整改投资、复核结论。台账只追加、不修改。
- `corrections.js` —— 指标更正以新条目留痕，必须展示原值、原来源、更正来源与理由；`metricHistory` 逐项列出指标沿革。
- `rules.js` + `fixtures/rules.json` —— 由景区与检查样例扩展的可执行规则（未闭环重大隐患、投诉逾期、数据更正线索、新业态无改善），以数据形式描述，可继续新增。
- `workflows.js` —— 三条退出流程各自独立：主动申请退出（申请→受理→公告→资产交割→注销）、行政摘牌（立案→调查→听证→决定→公告→摘牌）、降级（触发→整改令→整改→复核→恢复/维持/继续降级/摘牌）。每次流转校验经办人与随附要件。
- `policy.js` —— 整改期开放范围、预算占用、复核回避、公众公告四类政策按版本留存，任何时点可追溯到当时生效的版本。
- `evidence.js` —— 复核时按整改事项逐项汇集现场证据，恢复评级或继续降级均可出具逐项证据报告。
- `backend.js` —— `ScenicExitBackend` 门面，将台账、规则、流程与政策接线：登记资料、更正指标、执行规则、推进流程、出具复核结论。

运行 `npm test` 可查看复牌评审全链路示例：隐患已整改但投诉未决、客流数据被审计更正、新业态未改善经营时，规则触发发现项，复核回避与公告要件受控，最终逐项展示现场证据后方可继续降级。
