# 景区退出整改资产账

面向文旅主管部门的景区动态退出与资产盘活后台：保存景区评级检查、设施风险、整改项目和退出决定，复牌评审时逐项出示现场证据。

## 领域资料

`contracts/` 约定资料格式，`fixtures/` 提供不含真实个人信息的示例。代码模块只负责读取和校验这些资料，后续业务服务可以沿用其中的领域标识与版本约定。

当前资料记录了以下业务事实：

- 部分景区因安全管理、服务弱化和数据造假被处理
- 主管部门可采用抽查、暗访和游客反馈等方式监督
- 被降级景区尝试通过新业态改善经营
- 评级依据、明查暗访、游客反馈、设施风险、运营数据、整改投资与复核结论分账留存
- 主动申请退出、行政摘牌与降级分别适用不同流程
- 指标更正必须展示原值与来源
- 整改期开放范围、预算占用、复核回避与公众公告实行版本管理
- 恢复评级或继续降级须逐项出示现场证据

## 模块

- `src/ledgers.js` — 七类台账分账留存，只增不改；`buildDossier` 汇总单景区全量档案。
- `src/metrics.js` — 指标更正必须引用原条目，自动带出原值与原来源，更正链完整可查。
- `src/rules.js` — 由景区与检查样例扩展的可执行规则：投诉未办结、设施风险未闭环、客流更正核查、新业态佐证不足、整改逾期、反馈超期。
- `src/workflows.js` — 主动申请退出、行政摘牌、降级三套独立流程；公示须先有生效公告版本，申请复核须先有开放范围版本。
- `src/versions.js` — 整改期开放范围、预算占用、复核回避、公众公告的版本管理，按时间点查询生效版本。
- `src/evidence.js` — 现场证据登记与逐项覆盖报告。
- `src/review.js` — 复牌评审：汇总规则发现、逐项证据、生效政策版本与指标更正链，执行复核回避，给出恢复、维持、继续降级或摘牌结论。
- `src/loader.js` — 从 JSON 文档载入台账、政策版本与证据。

## 样例景区

`fixtures/scenic-spots.json` 中三家虚构景区对应三条主线：JQ-001 复牌评审（安全隐患已整改但投诉与设施老化未解决、客流指标被下修、新业态缺佐证）、JQ-002 主动申请退出、JQ-003 数据造假行政摘牌。编号均为虚构值，不包含账号、凭据或真实主体信息。

运行 `npm test` 可确认示例资料能够读取，且台账、规则、流程、版本与评审行为符合上述约定。
